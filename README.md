# 链上数据治理与血缘工作台

## 用途

多源链上数据接入、规范化、质量规则、血缘谱系、结构演进、快照版本比较与可复验导出。

本仓库是可持续演进的自托管 Go 应用。领域核心位于 `chainledger/`，命令入口位于 `cmd/chainledger/`。

```bash
go run ./cmd/chainledger demo
go run ./cmd/chainledger version
go run ./cmd/chainledger help
go run ./cmd/chainledger preview <graph.json> <plan.json>
go run ./cmd/chainledger apply <graph.json> <plan.json>
go run ./cmd/chainledger snapshot <graph.json> <snapshot.json>
go run ./cmd/chainledger compare <old.json> <new.json>
go run ./cmd/chainledger trace <snapshot.json> <dataset>
go test ./...
```

## 血缘批量调整（预览 / 应用）

一次提交多个数据集的血缘调整，先预览影响、再决定是否应用。新增命令读取两个本地 JSON 文件，分别保存当前血缘图和调整方案。

```bash
# 预览：输出报告，图文件保持原样
go run ./cmd/chainledger preview <graph.json> <plan.json>

# 应用：校验通过后把最终图写回原图文件，同时输出报告
go run ./cmd/chainledger apply <graph.json> <plan.json>
```

### 文件格式

图文件（`graph.json`）保存当前血缘图，只记录直接上游，下游关系由程序推导：

```json
{"datasets": [{"name": "A", "upstreams": []}, {"name": "B", "upstreams": ["A"]}]}
```

方案文件（`plan.json`）保存一批调整，每条记录包含数据集名称及其直接上游名称列表；顶层还可以有可选的 `removals` 名称数组，列出要从最终图中删除的数据集：

```json
{"changes": [{"name": "A", "upstreams": ["B"]}, {"name": "B", "upstreams": []}], "removals": ["C"]}
```

未提供 `removals` 或其为空数组时，`changes` 的既有行为不变。只有删除项的方案也应可用。

### 行为规则

- 一批调整可以登记新数据集，也可以替换已有数据集的全部直接上游；未出现在方案中的数据集保留原有直接上游。
- 同批新数据集可以相互引用，记录顺序不影响结果，合法性以全部替换和删除完成后的图为准。
- 空上游列表表示成为根。
- 名称区分大小写并保留空格，重复上游只算一次；仅改变输入顺序或重复上游不算变化。
- 方案中重复声明同一个数据集、名称为空或引用最终不存在的上游时，拒绝整批并说明涉及的名称和原因。
- `removals` 中的空名称、重复名称，以及同一名称同时出现在 `changes` 和 `removals` 中，都拒绝整批并说明原因。
- 删除当前不存在的名称视为没有变化，不列入实际删除结果；因此成功方案再次应用时仍能成功，所有变化和影响列表为空。允许删除全部数据集，结果是合法空图。
- 删除不能自动替下游删掉上游引用，也不能连带删除未明确列出的数据集。允许同批替换下游的全部上游，或把下游也列入删除；是否能提交，以所有删除和调整完成后的图为准。若保留的数据集最终仍引用已删除的名称，整批拒绝，错误说明引用者和被引用者。
- 最终存在自依赖或间接环的方案必须失败。
- 输入图自身存在空名称、重复数据集、缺失上游或环时也要拒绝，不能借调整方案掩盖原图的问题；原图本身损坏时，也不能靠删除问题节点让方案通过；空图允许登记一批新数据集。
- 空方案及相同方案的重复应用都应成功并返回空的变化和影响列表。

### 报告

预览和应用对同一当前图、同一方案的判断及报告一致。报告包含：

- 最终图
- 新增数据集
- 实际改变上游的已有数据集
- 本次实际删除的数据集（`removedDatasets`，没有实际删除时输出 `[]`）
- 增加和删除的直接关系
- 受影响的其他下游

删除节点连带消失的关系全部列入删除关系，删除项不混入新增或上游变化列表。受影响下游从实际变化的数据集出发，同时考虑调整前后的关系，实际删除的数据集也作为起点；排除已列为新增、直接变化或删除的名称，多条路径只计一次。关系被删除时也按原图计算影响。

报告和写回的图都使用 JSON，节点与名称列表按名称字节顺序排序，关系列表先按上游再按下游排序，空列表输出数组。相同当前图与方案即使记录和上游顺序不同，成功结果字节也应一致。

### 错误处理

读取失败、JSON 无效或无法完成图文件写入时，返回明确错误和非零退出码，不输出成功报告，原图文件完整保留（写入采用临时文件加原子重命名）。

## 本地血缘快照与版本比较

在一次血缘调整前后各保存一份只读快照，用比较命令看清派生数据的根来源是否改变。快照只记录数据集名称及直接上游关系，源图文件不会被修改。

```bash
# 保存当前图为版本化快照，成功后向标准输出打印内容标识
go run ./cmd/chainledger snapshot <graph.json> <snapshot.json>

# 只读比较两个快照（方向固定为旧 -> 新），向标准输出输出 JSON 报告
go run ./cmd/chainledger compare <old.json> <new.json>

# 只读追溯单个快照中某数据集的根来源，向标准输出输出 JSON 报告
go run ./cmd/chainledger trace <snapshot.json> <dataset>
```

### 快照格式

```json
{
  "formatVersion": 1,
  "contentId": "sha256:…",
  "graph": {"datasets": [{"name": "A", "upstreams": []}]}
}
```

- `formatVersion` 固定为 `1`；`contentId` 是 `sha256:` 加图语义的十六进制摘要；`graph` 保存完整图。
- 内容标识仅由图的语义决定。记录顺序、上游顺序、重复上游、JSON 空白不同但语义相同的输入，生成相同的内容标识与逐字节一致的快照，不受保存时间和文件路径影响。
- 读取快照时严格核对：缺少必要字段、不支持的格式版本、标识与图不符、JSON 无效，或图中存在空名称、重复节点、缺失上游、环，均拒绝并说明文件与原因，返回非零退出码且不输出成功报告。

### 保存规则

- 目标不存在：临时文件加原子重命名创建，写入失败不会留下半份快照；内容标识仅在成功写入后输出。
- 目标已是同一内容的合法快照：成功且保持原文件字节不变（幂等，mtime 也不变）。
- 目标内容不同，或是损坏文件：拒绝覆盖，原文件完整保留。
- 两个保存同时指向同一目标时，通过目标旁的锁文件串行化“检查—写入”过程：同内容皆成功，不同内容只有一个生效、另一个拒绝，目标始终为合法快照。

### 比较报告

比较方向固定为旧版本到新版本，报告字段包括：`newDatasets`、`removedDatasets`、`changedDatasets`（直接上游实际变化的共有数据集）、`addedRelations`、`removedRelations`、`rootSourceChanges`。

- 新增和删除的关系按集合差异计算；节点删除连带消失的关系也列入删除关系。
- 根来源是沿上游能到达的无上游数据集，根本身的来源包含自己，多条路径只计一次。
- `rootSourceChanges` 只覆盖两个版本共有的数据集，列出名称以及各自的新旧根来源集合；新增、删除的数据集不混入此列表。
- 仅调整路径但仍到达同一组根来源时，不报告来源变化。
- 空图可保存可比较；快照与自身比较时所有差异列表为空。节点与名称列表按名称字节顺序排列，关系列表先按上游再按下游排列，空列表输出 `[]`，相同语义的比较结果逐字节一致。`compare` 不写任何文件。

### 来源追溯

`trace` 回答“这个数据集的数据从哪里来”：只依据指定快照冻结的图，沿直接上游找出查询数据集可达的全部根来源，当前图后来的调整不影响该版本的查询结果。报告包含快照的 `contentId`、原样的查询名称 `dataset`，以及 `sources` 数组；每项给出 `root` 和 `path`——从查询数据集逐步沿直接上游走到该根的名称数组，首尾都包含在内。

- 同一个根可能经多条分支到达，每个可达根只报告一次，并给出一条尽可能短（直接关系数量最少）的路径；长度相同时，从起点向终点逐项按名称的 UTF-8 字节顺序比较，选第一次出现差异时名称较小的那条。不同根可以共享中间数据集，各自保留对应路径。
- 中间节点仍有上游时不算根；互不相连的数据集不进入报告；查询本身是根时只报告它自己，路径为单元素数组。
- 来源条目按根名称字节顺序排列；名称区分大小写并保留前后空格，路径始终用数组表达。记录顺序、上游顺序、重复上游或 JSON 空白不同但语义相同的快照，对同一名称的查询输出逐字节一致的报告。
- 查询前按既有规则验证整个快照；读取失败、JSON 无效、必要字段缺失、版本不支持、内容标识与图不符，或图中有空名称、重复数据集、缺失上游、环时，返回非零退出码并在标准错误说明文件与原因，标准输出为空。查询名称为空或不存在时同样失败并说明名称；空图合法，但其中没有可查询的数据集。参数数量不对时在标准错误输出用法并返回非零退出码。`trace` 不写任何文件，也不创建锁文件。
