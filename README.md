# 链上数据治理与血缘工作台

## 用途

多源链上数据接入、规范化、质量规则、血缘谱系、结构演进、快照版本比较与可复验导出。

本仓库是可持续演进的自托管 Go 应用。领域核心位于 `chainledger/`，命令入口位于 `cmd/chainledger/`。

```bash
go run ./cmd/chainledger demo
go run ./cmd/chainledger version
go run ./cmd/chainledger help
go test ./...
```

## 血缘批量调整（预览 / 应用）

一次提交多个数据集的血缘调整，先预览影响、再决定是否应用。新增命令读取两个本地 JSON 文件，分别保存当前血缘图和调整方案。

```bash
# 预览：输出报告，图文件保持原样
go run ./cmd/chainledger preview <graph.json> <plan.json>

# 应用：校验通过后把最终图写回原图文件，同时输出报告
go run ./cmd/chainledger apply <graph.json> <plan.json>
```

### 文件格式

图文件（`graph.json`）保存当前血缘图，只记录直接上游，下游关系由程序推导：

```json
{"datasets": [{"name": "A", "upstreams": []}, {"name": "B", "upstreams": ["A"]}]}
```

方案文件（`plan.json`）保存一批调整，每条记录包含数据集名称及其直接上游名称列表：

```json
{"changes": [{"name": "A", "upstreams": ["B"]}, {"name": "B", "upstreams": []}]}
```

### 行为规则

- 一批调整可以登记新数据集，也可以替换已有数据集的全部直接上游；未出现在方案中的数据集保留原有直接上游。
- 同批新数据集可以相互引用，记录顺序不影响结果，合法性以全部替换完成后的图为准。
- 空上游列表表示成为根。
- 名称区分大小写并保留空格，重复上游只算一次；仅改变输入顺序或重复上游不算变化。
- 方案中重复声明同一个数据集、名称为空或引用最终不存在的上游时，拒绝整批并说明涉及的名称和原因。
- 最终存在自依赖或间接环的方案必须失败。
- 输入图自身存在空名称、重复数据集、缺失上游或环时也要拒绝，不能借调整方案掩盖原图的问题；空图允许登记一批新数据集。
- 空方案及相同方案的重复应用都应成功并返回空的变化和影响列表。

### 报告

预览和应用对同一当前图、同一方案的判断及报告一致。报告包含：

- 最终图
- 新增数据集
- 实际改变上游的已有数据集
- 增加和删除的直接关系
- 受影响的其他下游

影响范围从新增或上游实际变化的数据集出发，包含在变更前或变更后沿下游关系能够到达的数据集，排除已列为新增或直接变化的名称，多条路径只计一次。关系被删除时也按原图计算影响。

报告和写回的图都使用 JSON，节点与名称列表按名称字节顺序排序，关系列表先按上游再按下游排序，空列表输出数组。相同当前图与方案即使记录和上游顺序不同，成功结果字节也应一致。

### 错误处理

读取失败、JSON 无效或无法完成图文件写入时，返回明确错误和非零退出码，不输出成功报告，原图文件完整保留（写入采用临时文件加原子重命名）。

## 血缘快照与版本比较

保存一次血缘调整前后的状态，并看清派生数据的根来源是否改变。

```bash
# 保存当前图为快照
go run ./cmd/chainledger snapshot <graph.json> <snapshot.json>

# 只读比较两个快照，向标准输出返回 JSON 报告
go run ./cmd/chainledger compare <old.json> <new.json>
```

### 快照文件

快照文件（`snapshot.json`）保存格式版本、内容标识和完整图：

```json
{"formatVersion": 1, "contentId": "<sha256>", "graph": {"datasets": [{"name": "A", "upstreams": []}, ...]}}
```

内容标识由图的语义决定：对规范化后的图（节点按名称排序、上游去重排序）计算 sha256。记录顺序、上游顺序、重复上游和 JSON 空白不同的等价输入，生成的标识及快照字节一致，不受保存时间、文件路径影响。

### 保存规则

- 保存不改变源图。
- 目标已有同一内容的合法快照时成功且保持原文件字节；已有不同内容或损坏文件时拒绝覆盖，原文件保持不变。
- 两个保存操作同时指向同一目标时也遵守上述规则（检查与创建为原子操作）。
- 写入失败不得留下半份快照；成功后才向标准输出输出内容标识。

### 比较报告

比较方向固定为旧版本到新版本，报告包含：

- 新增、删除、直接上游实际变化的数据集
- 增加和删除的直接关系（节点删除连带消失的关系也列出）
- 两个版本共有的数据集中，根来源集合发生变化的名称及各自的新旧集合

根来源是沿上游能到达的无上游数据集；根本身的来源包含自己，多条路径只计一次。新增、删除的数据集不混入根来源变化列表；仅调整路径但仍到达同一组根时不报告来源变化。空图可以保存和比较；同一快照与自身比较时所有差异列表为空。

读取快照时核对内容标识与图是否对应；缺少必要字段、不支持的格式版本、标识不符、无效 JSON 或图中空名称、重复节点、缺失上游、环均拒绝，错误说明涉及的文件和原因，返回非零退出码且不输出成功报告。
